## Delivered model and rendering

The [masterplan](../models/masterplan.blend) and [component masters](../models/architecture/) retain linked meshes and editable materials. The [full exterior](../dist/assets/brigade-barcelona.glb) and [compact exterior](../dist/assets/exterior-lod.glb) contain mesh instancing, Meshopt geometry and embedded KTX2 textures. The browser draws the compact asset first and loads the detailed model after the first draw on desktop. Cinematic raises desktop pixel-ratio and shadow-map caps, High uses detailed geometry within range, Performance stays on the compact model and Auto can lower resolution during sustained slow camera motion.

The podium has a 1024 × 1024 Cycles ambient-occlusion bake. Its materials reference a dedicated second UV set as glTF `occlusionTexture.texCoord = 1`. The browser uses that atlas for ambient occlusion alongside dynamic direct shadows. The browser capture harness observed five podium materials using UV channel 1 in visible draws. A scene-wide indirect irradiance bake and a unified cross-material texture atlas remain outstanding. [Runtime capture evidence](../qa/evidence/exterior-rebuild/capture.json) · [Surface scans](../dist/assets/textures/architecture/SOURCES.md) · [Fern model](../models/vegetation/README.md) · [HDRI credits](../dist/assets/sky-light.LICENSE.txt)

Crown profiles, façade construction, railing and glazing assemblies, podium heights, landscape palette and clubhouse pieces are modeled interpretations from the available brochure art and plans. Approved elevations, façade schedules, structural sections, planting schedules, measured vertical reference and as-built neighborhood assets would support a more exact reconstruction. The comparisons still show a gap to the requested photorealistic brochure benchmark, especially in landscaping, glazing and site integration.

## Geographic evidence

The November 27 public metadata probe confirmed 0.31 m native Esri World Imagery coverage at the plot, cached through zoom 19. The authenticated developer endpoint requires an operator token. Measured image horizontal accuracy is listed as 8.47 m. World Elevation has 24.74 m and 30.92 m sources at the site, while the tested Esri 3D layers returned local untextured geometry. The public search established no verified textured mesh for Kokapet. The open fallback remains native 10 m Sentinel-2 imagery and SRTM-derived terrain on a 32 m grid. The local browser capture used the Sentinel fallback. Location retains the optical imagery and mapped footprints. Showcase grades the terrain with an explicitly illustrative surface finish. Context building materials and roofs are varied over the existing footprints, whose heights and roof shapes remain approximate. ## Rendering feasibility

| Approach | Visual quality and browser access | Hosting, cost and integration |
| --- | --- | --- |
| Blender assets and Three.js | This build runs interactively in WebGL2 and reuses the buyer journey. Scene-wide indirect bakes, hero-grade plants and verified close-range context could close part of the remaining visual gap. Mobile quality still depends on the client GPU. | Static asset hosting. Cost scales with asset storage and delivery. Existing navigation, selection, maps and shared URLs can use the same assets and semantics. |
| Unreal Engine with Pixel Streaming | Server-side rendering can provide richer real-time lighting and shadows. Desktop and mobile browsers receive WebRTC video and send input. Compression, latency and connectivity affect the delivered image and interaction. | Requires render and encoder-capable server GPUs, signalling and potentially TURN or an SFU. Cost scales with active sessions, encoder capacity and egress. The HTML buyer app would need an Unreal event bridge for the wing, floor, amenity and residence identifiers. [Epic hardware and browser reference](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-pixel-streaming-reference) · [Epic hosting guide](https://dev.epicgames.com/documentation/unreal-engine/hosting-and-networking-guide-for-pixel-streaming-in-unreal-engine) |
| Babylon.js WebGPU with WebGL fallback | HDR/PBR and WebGPU are available in the browser. Mobile fallback quality depends on hardware. The same architectural inputs would still require reconstructed detail and lighting calibration. | Static hosting with client rendering. A renderer migration would require wiring the camera, GIS layers, picking and buyer transitions again. [Babylon.js WebGPU documentation](https://doc.babylonjs.com/setup/support/webGPU) · [Babylon.js HDR/PBR documentation](https://doc.babylonjs.com/features/featuresDeepDive/materials/using/HDREnvironment) |
