# Geographic exterior and balcony architecture

The buyer experience uses one registered Three.js camera for the city approach, site, wing and floor. The default route starts at the requested tower-wide framing and runs the existing 8.9-second building introduction. **Location → Fly from Hyderabad** and the journey URL add a regional flight ending at the exact first pose of that introduction. The regional map is an optional, independently loaded MapLibre view. [Building-first experience](http://127.0.0.1:5173/experience/) · [City flight](http://127.0.0.1:5173/experience/?scene=journey)

## Renderer decision

| Option evaluated | Implications for Plot 20 |
| --- | --- |
| ArcGIS Maps SDK SceneView | Integrates hosted terrain, authenticated scene and imagery services. The local 3D object layers inspected at Plot 20 contain untextured geometry. Porting the custom tower into a second scene engine would also require migrating façade ray hits, floor bands, design pick targets, camera paths and mobile fallback behavior. |
| Existing Three.js with supported ArcGIS REST services | Reuses the existing GLBs, orbit, selection meshes, highlights and interior navigation. WGS84-indexed imagery, measured terrain, construction exclusions and independently licensed footprint meshes fit this renderer directly. This is the implementation in this release. |

The previous exterior loaded a 12.8 km color image, a limited OSM neighborhood model, illustrative roadside vegetation and a flat backdrop. The updated exterior draws a registered terrain mesh and streams the visible building and image tiles. The background model from the previous release remains available as an authoring asset. The active exterior and balcony no longer load it. [Coverage at Plot 20](GEOGRAPHIC_COVERAGE_REPORT.md)

## Geographic frame and data

- The model origin is **78.312086932° E, 17.402192529° N**. Local coordinates are metres, with Y up. The X/Z vector for true east is (−0.233699171, −0.972308952), and true north is (−0.972308952, +0.233699171). The 16 HMDA coordinates enclose about 16,440 m² in this frame. Four brochure-to-parcel control points fit with a 1.033 m RMS residual. The developer’s tower set-out, floor heights and gate siting remain approximate. Full wing footprint and raw-source validations accompany the registration. [Parcel QA](../qa/parcel-registration.json) · [Geometry checks](../qa/geographic-geometry.json)
- The shared terrain sampler reads a 449 × 449 signed grid at 32 m intervals, covering ±7,168 m in each local axis. Site zero corresponds to a DEM estimate of 596.286 m on the EGM96-based elevation surface. A level conceptual pad blends into neighboring samples. Every building base and optional map stroke uses the same triangular surface. An outlying regional mesh provides 8,181 broader samples across the Hyderabad mosaic. [Elevation metadata](../dist/assets/geography/elevation.json) · [Regional terrain generator](../scripts/prepare_region_terrain.py)
- Three distance bands use mapped building footprints within 500 m, 2 km and 5 km. Courtyards, source heights, floor-count-derived heights, estimates and cleanup criteria are documented separately. Each 512 m tile is bounded, frustum-tested, batched, streamed and subsequently evicted. The desktop and mobile profiles use different budgets. The LODs of the architectural model retain the existing instanced façade elements. [Building data sources](BUILDING_DATA_SOURCES.md)
- Actual roads and vegetation first appear in the imagery. The optional **Mapped roads, paths and land use** control adds ground-following OSM linework and mapped tree points. The street camera stands 1.7 m above the terrain at (−46.19, 76.54) on tertiary way 1183681598, outside the gate-side boundary. The map overlay identifies mapped construction and water features, and parcel landscaping belongs to the conceptual project model. [Infrastructure inventory](../dist/assets/geography/infrastructure.json) · [Mapped road](https://www.openstreetmap.org/way/1183681598)
- Esri imagery is camera-refined, capped by published source metadata and actual tile availability, with a progressive Sentinel fallback. The region-wide flight uses locally registered, coarser imagery outside the neighborhood. The browser-restricted key is read from runtime configuration. [Integration and attribution](ESRI_INTEGRATION.md)

## Building, interior and outlook

The city flight and building introduction share their end/start eye, target and field of view. A 360° orbit, street camera, sunlight presets, tower ray picks and floor highlights operate in the same metre space. The original apartment-preload, dissolve and return logic connects wings and floors to the thirteen interior GLBs. Reduced-motion preferences, skip controls and direct links remain available. Opening the regional map or an apartment suspends the exterior loop and stream requests. Closing the map releases its renderer. [Exterior controller](../dist/estate-scene.js) · [Buyer navigation](../dist/estate.js)

**Look out from the deck** moves the shared geographic group into the active apartment scene. The longest traced balcony railing is aligned with the outward edge of the apartment’s mapped floor-plate bay. The local apartment plan is a quarter turn from the tower axes. A selected floor uses the model’s 15 m first-floor base plus 3.05 m per storey. A design opened without a floor uses an explicitly labelled illustrative 70 m datum. The buyer can turn and walk on the deck. Leaving the deck releases the geographic group back to the exterior. Possible future development and measured apartment sightlines remain unknown. [Floor-plate traces](../dist/floor-plate.js) · [Apartment renderer](../dist/app.js)

## Reproduction and acceptance

Run the build and local server from the repository root. The included open datasets support inspection on a disconnected network. An authorized browser-restricted key enables the live World Imagery endpoint after a refresh. The source ZIP supplies checked-in assets, reproduction scripts, source metadata, comparisons and QA results. The license holder controls deployment origins and service access.
